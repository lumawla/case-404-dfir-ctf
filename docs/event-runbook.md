# Event runbook — CASE 404

Spoiler-free. The answer sheet for facilitators is `private/organizer/ANSWER_KEY.md`.

Proposed event: Thursday 5 November 2026, 18:30–20:15: a 20-minute introduction, 10 minutes in the practice room, then the 75-minute investigation. Room to be confirmed (ELH/ALH). If the room is only booked until 20:00, set *Duration* to 60 minutes.

## Hosting it online for free

### Recommended: an organizer laptop + a free Cloudflare tunnel

No account, no card, real `https://` link, and the database stays on the laptop, so nothing is lost if something restarts.

1. On the laptop: install Node.js 22.13+, clone the repo, run `npm install` once.
2. Install Cloudflare's free tunnel tool (then open a **new** terminal):
   - Windows: `winget install --id Cloudflare.cloudflared`
   - macOS: `brew install cloudflared`
   - Linux: see developers.cloudflare.com → cloudflared downloads
3. Run **`npm run host`**. It builds the current source every time, starts the server and prints:
   ```text
   Players open:     https://some-random-words.trycloudflare.com
   Organizers open:  https://some-random-words.trycloudflare.com/admin
   Organizer token:  …
   ```
4. Put the players' link on the projector (or as a QR code). Sign in at `/admin` with the printed token.

Keep the laptop **plugged in, awake and online** for the whole event, and keep the terminal window open (on a Mac the script prevents sleep automatically). The link is new each time you run `npm run host`, so start it on the day, and do a test run the day before. Restarting is safe: teams, scores and join codes are kept in `data/`. Cloudflare's account-less tunnels come with no uptime guarantee, so have a phone hotspot ready as a backup connection.

### Persistent Render hosting

The repository's [`render.yaml`](../render.yaml) now selects a paid Starter service and a persistent `/var/data` disk. Follow [the deployment and rollback instructions](event-readiness.md) before applying it. Preserve the existing database and signing secrets explicitly when replacing an older ephemeral service; applying a blueprint does not transfer old data automatically. Automatic deploys remain disabled.

**Upgrading from an earlier version:** incompatible databases stop startup without being moved or reset. Schema 3 remains compatible. Back up and test any required migration offline before the event.

Any other host works the same way: Node 22.13+, `npm ci --include=dev && npm run build`, `npm start`, a persistent `data/` folder, HTTPS, and the environment variables below.

## Before the event (T−1 week to T−1 hour)

1. **Deploy** one instance behind HTTPS:
   ```bash
   npm ci && npm run build
   NODE_ENV=production ADMIN_TOKEN=<32+ random chars> APP_SECRET=<32+ random chars> TRUST_PROXY=1 npm start
   ```
   Or `docker build -t case404 . && docker run -p 8787:8787 -v case404-data:/app/data -e ADMIN_TOKEN=… -e APP_SECRET=… case404`.
2. **Freeze evidence:** run `npm test`. The content tests confirm the door-log hashes, the intake manifests, EXIF times, which act each file opens in, and the continuity rules. Don't edit `content/evidence/` after this. (Record evidence is generated by `npm run evidence`, images and the PDF by `npm run assets`; both are deterministic and committed.)
3. **Sign in** at `/admin` with `ADMIN_TOKEN` and set:
   - *Duration* 75 min (the default), *Min/Max team* (default 2–3; set 1 to allow solo players, 4 for larger groups).
   - *Event code* if you want only people in the room to create teams (show it on the projector).
   - *Teams may press Begin*: turn **off** if everyone should start together, then on at the start signal.
   - *Scoreboard visible to players*: off to reduce pressure; you can always see it at `/leaderboard` while signed in as organizer.
   - *Spoiler reveal time*: leave blank and use **Reveal solution now** after the last team finishes.
4. **Rehearse** with two test teams, one on a phone: join → practice room (try a task) → begin → own both Act I challenges and watch Act II open → from the admin page, **Open Act III** for the other team → file a wrong accusation → admin reset. Then reset the test teams (Manage → Reset).
5. **Venue:** test Wi-Fi from the room, have a backup hotspot, put the landing page or `/leaderboard` on the projector.

## During the event

| Time | Action |
|---|---|
| 18:30 | Introduction (forensics, metadata, Caesar, hashes, alibis) and a two-minute terminal primer: `ls`, `ls -a`, `cd`, `cat`, `grep`, pipes, `help`. Teams create or join on their devices. |
| 18:50 | Teams open the **practice room** from their lobby: a small folder, four warm-up tasks and the cheat sheet. Nothing there is scored and no clock runs. |
| 19:00 | Turn on *Teams may press Begin* if it was off. Each team's 75 minutes start when **they** press Begin. |
| Every ~15 min | Publish an announcement with the time left (Announcement panel). Watch the *Act* column: a team still in Act I after ~25 minutes may need help with a command, or an early act. |
| 20:15+ | When every team shows SOLVED, WRONG_VERDICT or TIME_EXPIRED, press **Reveal solution now** and present the reconstruction. |

The case opens in three acts. Act II opens for a team when it owns both Act I challenges; Act III when it owns any two of the three Act II challenges. Each act mounts new evidence in the team's terminal and puts new challenges on the board. Accusations open with Act III.

There are no in-game hints, by design. Facilitators may explain how a command works (`help <command>` shows examples, and so does the Cheat sheet tab), what `-a` does, how pipes work and what a hash or EXIF is. They must not point to files, name the Caesar shift, or confirm suspects, flags or theories.

## Emergencies

| Situation | What to do |
|---|---|
| Wi-Fi or server outage for everyone | **Pause event for everyone** (enter a reason). Clocks freeze and submissions are refused. **Resume** shifts every active deadline by the paused time. Both actions are audit-logged. |
| One team lost time (device died, network) | Manage → **Time extension** (1–60 min, reason required). This also reopens a team that already timed out. |
| A team is stuck at an act boundary | Manage → *Acts* → **Open Act II** or **Open Act III** (uses the reason field; audit-logged). Their terminal mounts the new evidence and the team sees the act's briefing. Acts never close again. |
| A team lost its join code | Members who are still signed in see it in the lobby. Otherwise Manage → **Regenerate join code** (the old code stops working; existing members stay signed in). |
| Player switched device | Rejoin with the same code, nickname **and private recovery key** from the old device's lobby. Verified recovery works even with registration closed or a full team, and preserves the old session. See [recovery details](event-readiness.md). |
| Wrong person joined a team | Manage → Members → **Remove**. |
| A team must start over | Manage → type the exact team name → **Reset team** (reason required). This deletes flags, accusations and the clock, and keeps notes. |
| Server restarted | Nothing is lost (SQLite file). Teams refresh their page and the clock resumes from the stored deadline. |

## After the event

1. Scoreboard: ranked by score; ties go to the team that reached that score first.
2. **Export CSV** from the dashboard. It contains team names, scores, status, flags solved and times, never notes.
3. Each team's accusations (suspect, motive, cited files) are under Manage → *Accusations*.
4. Retention: delete `data/case404.db` (nicknames, notes) within the retention period you announced, e.g. 30 days.
